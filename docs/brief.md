# Luna 网站体验审查任务书

本仓库用于审查并优化 <https://luna.nodesk.tech/> 的基础体验、文案和首次访问流程，并研究可借鉴的成熟方案。工作应从首次访问者的实际问题出发，以可复查的页面、交互和资料证据决定优先级。

## 已确认的目标与边界

- 审查首次访问者能否理解网站的用途、价值及下一步行动。
- 研究基础体验、文案、访问到转化的流程，以及移动端使用体验。
- 参考成熟产品和公开研究，提出适合本站场景的改进方案。
- 为这项工作建立独立的 `addapaw` GitHub 仓库；GitHub 端创建是否完成，以实际 API 结果及远端校验为准。

目前尚未确认网站所属产品、目标人群、核心任务、主要转化事件、商业模式及应用源码位置。现有 `chenwei.github.io` 仓库与 Luna 的关系也未建立，不能把其中的静态首页或 Notebook 当作 Luna 的实现。

以上未知项不阻止公开页面审查，但会影响转化指标、文案表达和实施方案。先通过实际页面建立初步假设，再将需要产品方确认的内容单独列出。

## 当前证据状态

**尚未形成任何关于 Luna 页面质量的结论。** 当前环境访问目标网站被代理以 HTTP 403 拒绝，尚未取得页面正文、截图或交互记录。网络访问问题是环境限制，不能视为网站自身故障。

不据此声称网站存在导航、文案、性能、无障碍或转化问题；不编造访问数据、用户反馈、页面元素或替换文案。下列内容是待执行的审查清单。

## 审查顺序与验收证据

| 顺序 | 要回答的问题 | 待执行检查 | 应保留的证据 |
| --- | --- | --- | --- |
| P0：首次理解 | 访客能否说清这是给谁、解决什么问题，以及为何值得继续？ | 检查首页标题、说明、首屏内容、产品示例和主行动按钮之间是否一致；区分访客可见事实与审查者推断。 | 页面地址、视口、截图、原文摘录、首次访问任务及观察记录。 |
| P0：核心行动 | 访客是否能完成本站实际支持的主要任务？ | 从真实入口走完注册、试用、咨询或其他已确认的转化流程；检查步骤、前置条件、费用说明、错误提示和成功反馈。未确认流程前不假定本站有这些功能。 | 每步页面、操作和结果；失败时的复现步骤及影响范围。 |
| P1：文案与信任 | 文案是否具体、易懂，并提供决策所需的信息？ | 核对术语、按钮动词、信息层级、重复与歧义；检查价格、限制、隐私和服务承诺是否与相关行动相邻且可理解。 | 原始文案、对应任务、问题依据；改写建议须标明需要验证的产品事实。 |
| P1：导航与返回 | 访客能否找到信息、理解当前位置并从中断处继续？ | 检查导航命名、链接目标、返回行为、空状态和错误状态；记录外链与上下文切换的实际影响。 | 入口和目标地址、任务路径、状态截图、可复现的阻碍。 |
| P1：移动端与无障碍 | 不同设备及输入方式能否完成同一核心任务？ | 检查窄屏重排、缩放、触控、键盘操作、焦点顺序和可见性、语义结构、表单标签、替代文本及对比度；自动检查后仍需人工验证。 | 测试设备或视口、浏览器、键盘路径、检查工具版本和人工验证结果。 |
| P1：性能与稳定性 | 页面是否在实际条件下及时呈现并稳定响应？ | 记录资源加载及网络失败；条件允许时检查 Core Web Vitals 的现场数据与实验室结果，保留二者区别；检查脚本错误和主要流程的加载状态。 | 测试地址、时间、工具、设备与网络条件、报告；不把单次实验室分数当作真实用户表现。 |
| P2：改进验证 | 建议是否改善了用户任务，而不只是改变外观？ | 按任务影响、证据强度和实施成本排序；在获得源码及产品事实后提出具体变更；通过相同任务复测，条件允许时开展用户测试或受控实验。 | 改动前后材料、验收任务、通过与失败记录；无流量数据时不声称转化提升。 |

P0 表示首先检查，P1 表示随后系统检查，P2 表示形成建议并验证。该顺序不是对当前网站缺陷严重程度的判断。
